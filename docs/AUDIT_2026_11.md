# AlephTX audit and hardening — 2026-11-07

## Scope and evidence

Reviewed the Rust strategy, execution clients, per-order tracker, legacy ledger, configuration and shared-memory readers; the Go websocket ingestion, private-account events and writers; build/test tooling and operational cleanup. Production changes concentrate on `lighter_inventory_mm`, the active per-order-tracked path. No exchange credentials were used, no live orders were sent, and no strategy process was started.

The original portable test baseline had **157 passing and 5 failing Rust tests** after the Linux-only linker issue was isolated. Two failures asserted behavior opposite to the current urgency policy, two used inconsistent timing/TTL fixtures, and one exposed sub-step order inflation. Regression tests now cover the corrected risk and protocol behavior rather than simply removing failures.

## Findings and changes

| Area | Problem | Result |
| --- | --- | --- |
| Depth IPC | Go's header is 2,048 `uint64` versions (16,384 bytes), but allocation and Rust offsets assumed 8 bytes | Both sides share the real layout; field offsets, last-slot access and file extents are checked |
| Account IPC | Reader could truncate the producer file; two Go writers raced; copying an old position refreshed its apparent age | Read-only validated mapping, serialized writes, independent equity/position timestamps, and stale-account quote suspension |
| Event IPC | Ring wrap could tear an overwritten payload; loss was only logged | Generation seqlock, integrity-loss signal, sequence reset detection and a reconciliation gate |
| Market feed | Lighter incremental updates were treated as whole snapshots | Persistent ordered book, deletion/replay handling, invalid-value rejection and disconnect invalidation |
| Fill accounting | ACK/HTTP races, duplicate/late fills, zero sequence and REST snapshot races could release or duplicate exposure | Idempotent transitions, retained ambiguous reservations, cumulative lifetime metrics, and non-finite payload rejection |
| Recovery | REST absence and cancellation submission were mistaken for confirmed terminal state | Empty-book plus fresh post-action position confirmation is required; cleanup does not report success with residual or unknown exposure |
| Execution | Concurrent writers reused nonces; partial local signing leaked reservations; cancel failures returned success | Serialized signing/submission, register after all local signing succeeds, cancellation-safe uncertainty guard and propagated cancel failures |
| Numeric boundaries | Float casts silently saturated; rounded quantities could exceed requested size; arbitrary fractional ticks formatted incorrectly | Validate finite/range/precision, round size down, round prices within the requested bound, validate configured venue precision and support ticks such as 0.25 |
| Strategy risk | Urgency/deadband logic could enlarge orders after margin clipping; position limits grew with quote sizing | Apply inventory policy before the final hard position and margin caps; zero-risk sides cancel immediately |
| Pricing | Local touch adjustment could pull quotes through fair value; stale/invalid anchors and depth were usable | Fee-aware model prices retain their bounds, source-time freshness checks, spread sanity checks and finite validation |
| Inventory timeout | Every additional fill restarted the holding timer | Inventory age follows continuous exposure, including repeated accumulation |
| Hot paths | Volatility scanned the full window and anchor median allocated on each cycle | Incremental rolling statistics, stack-only anchor median and O(1) lifetime fill counters |
| Configuration | Missing/malformed files silently restored default risk parameters; exchange IDs disagreed | Explicit startup errors, numeric/window/risk validation, strict inventory-strategy keys and consistent exchange IDs |
| Tooling | No offline test target; build omitted Go; Linux signer linked unconditionally | Makefile build/test/check/benchmark targets, portable offline builds, Linux/macOS CI and explicit signer platform errors |

## Reproducible verification

```sh
make fmt-check
make check       # Rust clippy warnings are errors; Go vet
make test        # Rust offline lib/bin tests; Go race detector
make build       # Rust release binaries AND Go feeder
make benchmark   # ignored Rust comparative microbenchmarks; Go benchmem
```

Final local validation: **196 Rust tests passed**, **16 Go tests passed with the race detector**, and both explicitly invoked Rust microbenchmarks passed. Strict Clippy, Go vet, formatting checks and the combined release build passed. The two benchmarks are ignored by the ordinary test target, then run by `make benchmark`.

Tests use synthetic protocol and market scenarios. They include long/short inventory and cash-budget combinations, outliers and stale feeds, trending/dislocated quote scenarios, rolling-statistics equivalence across evictions, malformed/short SHM files, ring overwrite, duplicate/late fills, failed and canceled submissions, uncertainty recovery barriers, order normalization and configuration rejection. Credential-dependent signer initialization is explicitly ignored. Linux also checks that an uninitialized native client cannot sign. Examples that submit real orders are never executed by these targets.

GitHub Actions runs the same checks and build on Linux x86-64 and macOS. The Linux job additionally exercises native library linking; macOS deliberately rejects signer initialization instead of pretending to produce signatures.

## Local performance measurements

Apple M1 Max, Rust 1.95.0 release build, Go 1.27.1, measured during this audit. Rust comparisons run the previous algorithm and new algorithm with the same inputs in the same process; there are no timing pass/fail thresholds.

| Microbenchmark | Previous implementation | Updated implementation | Comparison |
| --- | ---: | ---: | ---: |
| Rolling volatility, 200-sample window, 200,000 updates | 39.684 ms | 3.591 ms | 11.05× |
| External median, 200,000 updates | 34.856 ms | 4.091 ms | 8.52× |
| Go 1,000-level book delta + top-five extraction | No comparable correct baseline | 593.7 ns/op | 0 B / 0 allocations |
| Go BBO publication | Not recorded | 7.137 ns/op | 0 B / 0 allocations |

These isolate local algorithms. They do not measure network latency, exchange matching latency, attainable fill rate or strategy returns. Host load changes absolute timings.

Private websocket subscriptions also have a fixed 15-second confirmation deadline and reconnect on explicit server errors; pings cannot keep an unconfirmed subscription alive.

## Deployment compatibility and remaining limitations

- Restart feeder and strategy together with freshly created SHM files. The corrected depth layout, ring generation and independent position timestamp must be deployed as one protocol version. Do not mix old and new processes. `make clean-shm` now includes the V2 ring; stop all users of the mappings before removing files.
- Lighter private position SHM represents **one market**. Feeder validation rejects multiple Lighter subscriptions. Match the strategy's market and normalized symbol to that single feeder market. Use only one trading process per account/API key; the nonce lock serializes one client, not multiple processes.
- Explicit `config.toml` is now required. Copy and review `config.example.toml`; risk settings no longer fall back silently. The active strategy validates tick/step against venue precision before starting.
- The repository bundles a Linux x86-64 signer from Go revision `219bdc7b6da26171fc2b7113a529091b72b51c28` (its embedded build metadata says modified). Its ABI was checked against that revision. The current SDK has a different ABI: do not replace the binary without matching bindings and native integration tests. This audit does not validate live signing, authentication or exchange acceptance.
- The account snapshot and event ring do not yet share an exchange-verifiable watermark. A delayed fill already reflected in a position snapshot can arrive after cleanup; atomic local cleanup does not solve that cross-stream ordering problem. Realized-profit attribution needs a cost-basis ledger: `trade_cash_flow()` exposes the existing cash-flow metric, and the legacy `realized_pnl()` alias is documented accordingly. Very late duplicate fills beyond the tracker retention window also need durable deduplication.
- REST open orders cannot explain a missing historical fill. Ambiguous submissions or event loss stop new risk taking and retain reservations. Recovery may require operator reconciliation; no guessed fill history or realized PnL is synthesized from account position.
- Position freshness is based on real position messages, not websocket pings. If the venue sends positions only on changes, a quiet account can conservatively pause after 30 seconds. Verify real subscription refresh behavior before live operation. Snapshot freshness is intentionally not fabricated.
- Legacy adaptive/backpack/EdgeX strategies remain older execution paths. This audit adds shared boundary checks and request timeouts, but does not claim the new Lighter reconciliation guarantees for those paths. EdgeX BigUint signature work still warrants separate CPU profiling/offloading and protocol-vector coverage.
- Go trade deduplication and filled-order metadata currently grow during a session. Long-running production sessions need a bounded retention design coordinated with exchange replay guarantees.
- No historical order-book/trade dataset or live execution benchmark was present. The replay scenarios establish invariants, **not profitability**. Maker/taker fees, latency, queue position, adverse selection and A-S volatility time units still require market-specific calibration and out-of-sample replay before claiming a return improvement.
