## 2. 官方规则复核及 Arcus 路线的准入边界

本轮实际取得官方正文和未鉴权的市场费表，并记录下载时间、内容 SHA-256、
来源域与可用性。它们是当前规则快照，不能倒填成旧回测时点已知的费用。

### Arcus

公开市场费表核实以下数值（单位 bp；负 maker 费为返佣）：

| 市场 | Tier 0 maker / taker | Tier 5 maker / taker | Tier 6 maker / taker |
| --- | ---: | ---: | ---: |
| BTC-USD | 1.50 / 4.50 | −0.20 / 2.00 | −0.30 / 1.90 |
| SPY / QQQ / GLD / NVDA-USD | 0 / 2.25 | −0.20 / 1.00 | −0.30 / 0.95 |

来源：[官方按市场费表](https://api.arcus.xyz/v1/markets/feeSchedules)。
表中的档位只是公开条件费率，未验证任何私有账户享有 Tier 5/6。

官方定义 maker share 为同一个滚动 30 日内的账户 maker 成交／全站 maker
成交，严格 **高于** 1.5%／4% 对应 Tier 5／6；同地址子账户共享，地址间
不合并。资格每日核查，通常一个工作日内应用；返佣还受同笔对手方 taker
实付费用封顶。当前取得的正文未注明 Gemini 所述 11 月 23 日生效日期，
不能用报告推定已应用。[官方费用规则](https://docs.arcus.xyz/concepts/perpetuals/fees)

这条路线值得独立研究，但“零 maker 费冷启动”只指一种费用为零，不能消除
逆向选择、平仓、资金费、融资与库存尾部损失。还要修正三项算术前提：

1. 不能用未核对口径的全站总成交量代替官方 maker-share 分母。若增量成交
   同时扩大分子和分母，需解 `(V + ΔV) / (D + ΔV) > s`；若采用已预测的
   最终分母，应明确这一不同假设。重复使用同一成交不能增加独立证据。
2. `ΔF_save / ΔV` 只是情景预算，不能把升档前成交追溯改用新档费率。
   必须计入滚动到期、资格生效延迟、同笔返佣封顶，以及尚未升档的失败路径。
3. 共用账户费率不允许三个研究项目相互补贴。每项目必须在自己的账本和
   亏损预算内成立；跨项目节费不得作为第三赛道的可用风险预算。未兑现积分
   仍按零现金，不采用 Gemini 的“确定性底仓收益”假设。

Arcus ALO 免 taker speed bump，取消有专门优先通道；但具体延迟是运营配置，
API 不暴露，也可能调整。因此不能把报告中的 50 ms 写成已证实常数。
[官方延迟说明](https://docs.arcus.xyz/guides/latency)

### Lighter

官方明确 quota 的动作消耗不同：Create、Modify、CancelAll、Grouped 消耗
额度，单笔 CancelOrder 不消耗；批次不能按一笔额度计算，免费发送还可能不
返回剩余额度。额度按 L1 地址共享。BTC/ETH/SOL 的当前默认是每 2 美元成交
补 1 额度；市场列表及 Core/RH ID 不可混用。
[官方额度规则](https://docs.lighter.xyz/developers/reference/volume-quota)

额度、交易类型限频、HTTP/WS 请求预算必须分开。Standard 仍有每分钟 60 次
的一般请求预算，付费档发送请求又有独立桶。文档对单笔撤单“无限频”的表述
不能据此当作所有请求预算都豁免；缺少实际账户和请求时序时保留未知。成交
量、撤单订单数的总和不足以检验回放是否满足滚动请求预算。
[官方限频规则](https://docs.lighter.xyz/developers/reference/rate-limits)

## 3. 已实现：分离 A-S 价差、贴盘和放置边界

新增 `diagnose_quote_constraints`，默认关闭，仅 `research-replay` 编译。
它在真实报价计算周围设定同步诊断作用域，排除 cross-market attribution
的反事实再次计算。所有计数固定大小，不存订单或账户身份，不修改报价结果。

- 基础价差计数识别原 A-S 半价差被下限抬高、上限压低、恰好相等、处于内部，
  以及上下限重合。这里配置值是**双边完整价差**：16 bp 对应每侧 8 bp，
  不能误当每侧 16 bp。
- 每侧分开统计向零库存方向及开仓方向的贴盘/交叉修正、放置边界收紧/相等/
  松弛，以及最终被动退出修正。向零方向不代表最终订单已经具有 reduce-only。
- `evaluated = quoted + unquoted`，成功计算的价差类别互斥且总和等于
  `quoted`。这些是报价候选次数，不是下单、成交次数或独立统计样本。

下限生效比例不能单独解释成交亏损；放置边界还混合费用、利润、锚和分位风险
准备。尤其不能因为少成交后现金变好就认定 alpha 有改善。新诊断的用法和
报告字段见[回放运行说明](PERP_RELATIVE_VALUE.md#recorded-maker-pricing-constraints)。

还需保留一个边界：减仓方向会按放宽后的利润目标重新计算基础价差，本轮
`base_spread` 计数没有声称覆盖这条二次计算。库存保留价中的 γ 也仍可能起
作用。因此，即使基础价差全部触及下限，也只能判定这一阶段的参数传导受阻，
不能宣称所有 A-S 参数、所有最终报价或库存退出都失效。
