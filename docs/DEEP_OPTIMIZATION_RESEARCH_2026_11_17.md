## 1. 核心判断：把报告的机制假设变成可归因、可执行的系统

两份报告值得认真吸收的共同主线是：**做市收益取决于报价在真正生效时是否仍有优势，而非发送时看起来有点差；新闻、跨所价格发现、队列位置、撤单延迟、资金费和保证金必须进入同一个因果执行模型。** 第一份更强调事件情报与状态切换，第二份更强调微观结构、场所规则与运行时。二者应合并为一套“证据 → 防御 → 报价 → 执行 → 归因”的闭环。

但报告并未直接审阅当前私库，若按其“从 v5 本地盲报价全面重建”的叙事开工，会重复实现已有能力，并把若干错误规则写进交易边界。当前已有跨所参考、方向性撤单、分签名通道、风险预留、连续回放和数据湖。正确路径是沿这些边界补缺口，优先证明收益来源，再决定是否改运行时、账户类型和部署地点。

**本方案的六个决策：**

1. **先校准执行与数据，再扩大策略搜索。** 场所/网络/账户类型的延迟、费用、取消生效、交易资格、数据可用时刻必须可追溯；否则任何 alpha 改进都可能只是模拟器偏差。
2. **优先做事件防御，事件进攻独立立项。** 可信事件可以先缩量、撤掉危险侧；新闻 IOC、链上预埋、清算捕获必须各自证明扣成本优势，不能借用做市风险预算。
3. **复用现有跨所信号，先做简单消融。** Binance veto、参考价、OFI、库存曲线、报价滞回逐项比较；GLFT、VPIN、多档 OFI 是候选模型，不能因为名字高级就替换当前基线。
4. **把执行能力做成版本化能力表。** Core 与 RH、Standard 与 Premium、单笔与 batch、普通 key 与 maker-only key都不能混用假设。调度器需知道动作何时可执行、消耗多少额度、失败后保留多少风险。
5. **安全边界只允许确定性代码决定。** AI 无签名密钥仍可能通过仓位额度控制交易风险；其输出默认只能降风险或提供候选事实。新闻 IPC 必须与私有订单事件隔离，撤单与恢复不得绕过终态证据。
6. **保留三条独立经济目标。** Quant 证明净现金优势；Arb 证明双腿可执行且风险闭合；Turnover 证明真实资格下的单位成本。积分估值、未平仓浮盈、恢复成交量不能补贴另一条赛道。

## 4. 目标架构：在现有三平面旁增加公共事件证据链

建议数据流如下，箭头不表示已实现：

```text
公开盘口/成交 ──→ 现有 Go feeder ──→ 现有 BBO / depth ──→ 确定性特征与报价
官方公告/新闻 ──→ event collector → 身份/修订/来源校验 → 独立公共信号 IPC ─┘
公开链上数据 ──→ 独立慢速研究管线 ──→ 经过批准的有限信号 ────────────────┘
                                                    ↓
                       状态/风险门控 → 预留敞口 → 执行调度 → 现有 signer
                                                    ↑
私有成交/仓位 ──→ 原有128B V2事件 → order tracker / journal / recovery
                                                    ↑
                          独立 riskd / 原生撤单租约（待验证）

所有公共输入 → 现有 capture/lakehouse；私有证据 → 隔离私有库；二者经受控归因关联
```

**A. 统一身份，禁止用 ticker 猜合约。** 注册键至少包含 `venue/domain/network/instrument_type/base/quote/settlement/multiplier/expiry`，内部 symbol_id、exchange slot、venue market_id各自独立。链上资产用 chain+contract；RWA补充 underlying、交易时段、公司行动、价格单位和参考市场。供应量或价格相差20%只能告警，不能自动判定同资产。USDC/USDG、spot/perp、不同预言机或不同乘数不能隐式互换。身份未确定时不向交易策略发布可执行信号。

**B. 事件记录是可修订事实，不是一条永久正确的新闻。** 建议字段：schema/version、source_id、channel_id、source_event_id、revision_id、canonical_asset_id、event_kind、direction_hint、severity、source_time及其精度/可信度、first_seen_wall、receipt_mono、available_mono、process_epoch、expiry、evidence_ref、content_hash、supersedes/retracts、coverage_state。大文本留公共证据存储，IPC仅传固定大小索引与确定性枚举。结构尺寸通过实际需求和 ABI 评审决定，不先拍定128B。

**C. 去重与可信度分开。** 报告的 `source_tier+symbol+action+60s` 哈希既不能跨层合并同一新闻，也会吞掉一分钟内两条不同公告。先按原始 ID/版本幂等，再按原始公告链接、合约、事件类型、事件生效时间建立可追溯关联；保留每个来源的独立证据。十家媒体转载同一公告不是十份独立确认；撤回和更正不能被 dedup 掉。

**D. 三类时钟不可混写。** source_time 是对方报告的事件时刻，receipt 是我们收到，available 是解析校验后策略可读取，journal/write是记录时刻。回放用 available 排序；跨机器 monotonic 不可直接相减，必须有校准与误差界。新闻平台推送时间不等于事件最初发生时间；AI 两小时内更新的摘要不能回填到首次新闻时刻。记录每次修订第一次可见的时间。

**E. 覆盖、断流和背压是一等状态。** 频道发现结果版本化；捕获订阅成功、首个有效消息、重连、游标缺口、限流和丢弃计数。最新状态 SHM 与逐事件 ring都需要版本/epoch与溢出检测。公共新闻过载：降为防御、禁止新进攻；私有订单事件缺口：按现有路径冻结并对账；两者不能共用同一“丢一条继续跑”的规则。

新闻源落地顺序：eqn 主流 WS 用于快速发现，MCP按游标补齐非主流与修订，RSS做慢速一致性审计；重大交易所事件优先保留原始官方公告。eqn 的 WS 心跳为文本 ping/pong，消息时间戳与 RSS 缓存语义需按文档实现。[eqn API](https://eqn.news/api) / [API docs](https://eqn.news/api-docs)

Binance 原生公告可作为对照源，但连接需要签名鉴权；签名URL、token和认证响应绝不能进入公共 capture、handoff或日志。断连重连和首次有效事件也要记录，不能只记连接成功。[官方公告格式](https://developers.binance.com/en/docs/products/announcements/announcement) / [连接要求](https://developers.binance.com/en/docs/products/announcements/general-info)

**AI 接口限制。** AI 可离线提取资产候选、事件类别、解释与证据引用；交易内核只接受 allowlist 中的有限字段，拒绝自由文本指令、过期数据、未解析资产和非有限数值。防御信号可在预设上限内降额；上调风险、切进攻模式、延长暴露时间必须由预先冻结的确定性政策决定。LLM调用、网络查询、文本解析和阻塞写盘都不进入报价热路径。

## 5. 事件与盘口的统一防御状态机

采用报告R1的分级思想，但把状态、订单动作和退出条件写清楚。**信号可信度、数据新鲜度、账户状态、执行能力四项共同决定状态**；新闻强度不能覆盖账户风险。

| 状态 | 触发依据 | 可执行动作 | 恢复条件 |
| --- | --- | --- | --- |
| NORMAL | 必需输入健康、风险余量足、无超阈事件 | 现有双侧报价与库存控制 | 持续满足准入 |
| CAUTION | 弱来源事件、参考分歧、流量异常、轻度陈旧 | 减量、加宽、缩短允许暴露；不自动增加方向仓位 | 证据过期/澄清且健康持续达滞回要求 |
| SIDE_DEFENSE | 可定位资产和方向的价格冲击/可信新闻，危险侧被穿透风险上升 | 禁止危险侧新单；撤该侧已知订单，安全侧仅在库存/保证金许可下保留 | 冲击衰减、参考恢复、取消回报与仓位确认 |
| HALT_RECONCILE | 私有流缺口、账户不确定、严重安全事件、亏损门限、风险超限 | 禁止增风险；发受控撤单请求；独立记录待决风险 | 权威终态、最新仓位/水位与双所恢复屏障全部通过；超时本身不恢复 |
| REDUCE_ONLY | 需降低已确认敞口且可用深度/保护满足 | 仅方向正确且不会翻仓的受限减仓；对冲按独立能力表排队 | 库存与未决风险均回到安全区 |
| EVENT_ATTACK | 仅独立实验策略通过准入后可达 | 专属预算、最大追价、期限和退出政策下的受控 IOC | 单次机会完成或失败即退出；不得借防御状态偷偷加仓 |

状态优先级：未知账户/硬风险 > 数据健康 > 事件防御 > 报价经济性。CAUTION不能降低HALT；新策略不能取消既有UTC每日亏损保护。作用域默认资产/市场；交易所安全事故才升级域，跨域风险确有证据才全局升级。

单侧撤单首先覆盖现有支持场景，再设计 hedge 模式扩展。待撤单仍可能成交，取消请求发出、HTTP成功、交易hash和订单真正终态必须分开。对危险侧维护 `cancel_requested → pending → terminal_confirmed`，在最后一步之前维持最坏敞口预留；同时观察已发在途创建，不能只撤当前 open-order 列表。

“误报先防御”也要计成本：统计停止报价时长、被避免的逆向成交、错过的正收益成交、过度取消、恢复迟滞与新闻风暴下可用性。安全恢复用独立健康证据和最小稳定期，不能让同一错误来源的“解除警报”直接重新开仓。

## 6. 定价与特征：修正公式，分离 alpha、库存和风险

**先解释R1公式的问题。** 令 `G = γ·σ_eff²·τ_eff`、`D = μ_eff·τ_eff`，报告给出的结构为：

```text
r  = S_fair + D − qG
δa = base + 0.5G(1−2q) − D + ζa
δb = base + 0.5G(1+2q) + D + ζb
Pa = r + δa = S_fair + base + 0.5G − 2qG + ζa
Pb = r − δb = S_fair − base − 0.5G − 2qG − ζb
```

因此 `D` 在最终报价中完全抵消，库存位移变为两倍；这不是文中声称的事件方向漂移。若q用币数、美元名义或归一化库存而G不变，量纲也不一致。必须先定义单位、边界与公式推导，再做回放。

**建议的可检验起点（设计，不是已校准模型）：**

```text
F       = fresh reference price + slowly estimated local basis
alpha   = bounded price-unit forecast at THIS action's effective horizon
x       = signed inventory exposure / configured risk budget
r       = F + alpha − inventory_penalty(x)
bid     = round_down_to_tick(r − nonnegative_bid_halfspread)
ask     = round_up_to_tick  (r + nonnegative_ask_halfspread)
```

alpha、库存价格惩罚和半价差都用相同价格单位；采用bps参数时统一经F换算一次。事件可增加半价差、降低规模或触发veto；不要在r与spread两处重复加入相同漂移。满足tick/lot/min-notional、PostOnly可执行性、单腿/净风险限额之后才可发单。即使数学报价有价格优势，门控仍可拒绝。

**参考价和 lead-lag。** 保留现有 allowlist median 作为稳健基线，以本地可用时刻构造领先所冲击。参考选择应按因果预测增益、费用后可执行性和稳定性评价；单纯94%跟随率不是94%盈利概率。目标所已经走完、手续费吃掉波动、或成交只发生在坏路径时，高方向命中率仍会亏。分别报告预测误差、触发覆盖率、真实成交条件下markout和撤单保护效果。基差EWMA只能用过去数据，切换参考或交易时段要有预热与回退。

**OFI / MLOFI / VPIN。** 当前BBO差分OFI可继续做低成本基线。读者跳过SHM版本时，它不等于逐更新订单流；应记录skip计数，必要时增加有序增量tap。MLOFI需真实多档、序列连续、可重建的深度；Binance当前BBO接入不能冒充20档。VPIN需成交方向和稳定量桶，方向未知时保留未知；用OFI近似值却标VPIN会误导比较。R2的0.35/0.6阈值只作候选，必须验证是否在控制波动和流动性后仍有增量解释力。

**GLFT与到达率。** 对 `λ(δ)=A·exp(−kδ)` 的拟合应使用每个价差、队列状态、存活时间对应的风险暴露时长；无成交窗口也是样本。只对成交记录回归会产生选择偏差；公共成交强度也不等于自己的成交强度。5秒更新/10分钟窗作为候选，加入最小样本、参数范围、估计不确定性、突变检测及保守回退。报价自身改变可观测成交分布，不能把策略选择当外生样本。[GLFT 原始研究](https://arxiv.org/abs/1105.3115)

**库存非线性。** 现有tanh规模偏斜无需推倒重来。比较线性惩罚、现有曲线和受界非线性；`atanh(clip(x,±0.95))` 是有限价格惩罚，不会强制仓位停止。硬库存、保证金、待决成交与损失限制必须在执行入口单独拒绝。接近上限时禁止增风险侧，而非依赖“报价足够远应该不会成交”。

**滞回应经济化，但不能拦安全动作。** 在当前滞回基础上比较：保留队列的预期价值、移价带来的条件markout改善、创建/取消延迟、额度机会成本。普通价格抖动可以不撤；账户不确定、严重陈旧、硬风险和危险侧冲击必须绕过经济滞回。2–3tick只适用于特定ticksize与波动尺度，不能全市场复制。

**量纲纪律。** 波动率需明确采样间隔、收益定义和年化/每秒单位；执行期限τ使用实际动作分布，而非一个全局常数。VPIN、OFI、库存比例与价格漂移分别命名。单元测试检查零信号对称、漂移符号、库存增大时减风险方向、有限数值、tick舍入与极端跳变，不为每个参数堆“复述实现”的测试。

## 7. 执行经济学：延迟、额度、签名通道和价格边界

**A. 建立能力快照，而不是全局 `taker_delay_ms`。** 以下是本轮官方页面给出的基础规则，单位ms；不包含网络、签名、客户端排队、venue抖动。实现时保存来源URL、查询日期、规则版本、适用网络与账户条件，不应硬编码成永恒常量。

| 域 / 账户类型 | Maker | Cancel/Modify | Taker | 研究含义 |
| --- | ---: | ---: | ---: | --- |
| Lighter Core Standard | 0 | 300 | 300 | 挂单快并不意味着撤得快；旧报价风险集中于取消窗口 |
| Lighter Core Premium | 0 | 0 | 140 | 吃单仍有显著延迟，不能当作新闻15ms套利腿 |
| Lighter RH Standard | 200 | 200 | 300 | 创建、取消、对冲分开建模；不得套Core Standard |
| Lighter RH Premium | 0 | 0 | 200→150 | 取决于适用的14日成交量档位，不能套Core140 |
| Backpack | PostOnly豁免 | Cancel豁免 | 非PostOnly为100 | 非PostOnly限价单即使最终挂住，也不自动免延迟 |
| edgeX / 新场所 | 待核验 | 待核验 | 待核验 | 未知就是未准入，不填0 |

来源：[Core账户规则](https://docs.lighter.xyz/developers/reference/account-types)、[RH规则](https://docs.lighter.xyz/developers/robinhood-chain/overview)、[Backpack API](https://docs.backpack.exchange/)。网络domain还包括endpoint、chain与结算资产：测试链ID可能重合，不能仅靠chain_id辨识Core/RH。

事件效果的正确时钟是：`available → feature_ready → decision → risk_reserved → signed → socket_sent → accepted → order_effective → fill/terminal`。HTTP返回不是入簿，撤单ACK不是撤单生效；没有直接可观测点就报告区间/代理及误差。分别测创建、改单、撤单、IOC与重连后的p50/p95/p99，包含高负载和事件突发；不把均值填进所有回放订单。

**B. Premium/Plus 升级要算净收益。** Core Standard和Premium的费用结构不同，RH也不同；不能只拿0ms撤单的优势比较。对同一冻结策略计算：

```text
升级净增益 = 避免的逆向成交损失 + 新增可实现点差/交易机会
           − 全部受影响成交的增量手续费 − 额外对冲/融资/运行成本
```

采用账户实际可得费率，不假定已享质押折扣、VIP、返佣或AutoLend。可提前做多费率敏感性区间，真正变更账户类型、质押或资金安排需另行授权。Backpack AutoLend作为资金可用性/借贷机制研究，不能与毫秒级可撤风险余额混为一谈。

**C. Volume quota是可观测资源账本。** 现有响应结构主要保留tx_hash；应增补额度字段、缺失/陈旧状态、请求分类、预计消耗、实际返回、相关账户作用域及服务器重置规则。Core Plus/Premium的官方说明中单笔CancelOrder与Create/Modify/CancelAll/Grouped的消耗不同；`SendTxBatch` 不能假设整批只消耗一次。独立bid/ask不能伪装成OTO/OCO节省额度。[额度规则](https://docs.lighter.xyz/developers/reference/volume-quota)

研究预算可写成 `预计额度变化 = Σ(经确认的合格成交额 / 对应额度生成单位) − Σ动作消耗`，但这是规划估计，服务端余额才是可用上限证据。不同市场单位、舍入、共享账户和异步入账都要验证。C2F/OTR仅是描述指标：高名义低笔数与低名义高笔数的额度可持续性不同，不能用“OTR<6”作为通用充分条件。

调度优先级：风险减缓动作 > 必要对冲/退出 > 维持安全报价 > 新增alpha报价。即便单笔取消不消耗volume quota，仍可能受网络、API限流、nonce与签名队列约束。保留安全容量；若剩余额度未知或低于门槛，停止可选创建、减少改单，不能通过制造成交补额度。每赛道分别归集其资源消耗，不用共享账户掩盖亏损。

**D. 三通道是在现有实现上补能力校验。** 当前可选独立Maker/Cancel/Taker，未配置时会回落共享通道。启动报告应明确实际映射与是否隔离；通道分离只能避免客户端部分队头阻塞，不保证交易所并行撮合。Premium maker-only venue标志与本地“叫作maker的key”不是一回事；其限制、读回状态和冷却需单独确认。[API keys](https://docs.lighter.xyz/developers/integration-guides/api-keys)

每个key的nonce序列仍须单一所有者；不能让主进程与riskd抢同一个nonce，也不能以获取nextNonce就证明此前订单不存在。保留当前不确定提交失效/重取策略，增加可审计的 intent→submitted→accepted/uncertain→terminal 关联；只记录非敏感状态摘要到公共监控，签名请求与账户标识保留私有证据库。若扩展journal，先在离线schema中做兼容与故障验证，不自动推广schema3到live。

**E. 本地价格保护必须覆盖所有发单路径。** 官方说明sendTx与sendTxBatch的fat-finger行为不同，batch路径不能依赖同一服务端默认。保护需同时限制相对可信参考的偏离、相对可执行盘口的滑点、最大名义、可用深度、tick/lot和reduce-only方向。未知参考时拒绝新增暴露；紧急减仓使用独立但有上限的政策，而非无限价追单。[Order types and matching](https://docs.lighter.xyz/trading/order-types-and-matching)

## 8. 独立风控、撤单租约与恢复：做失效隔离，不做第二个盲下单器

**保留已有安全不变量。** 创建/改单前先预留最坏暴露；pending cancel、提交不确定、私有流缺口期间不释放。终态需绑定同账户、域、市场、订单身份，并满足适用的仓位新鲜度/成交水位。空open-order列表或超时不能单独证明安全。双所恢复完成前不清journal；只读audit不能授权重启。

**riskd的新增价值是进程故障隔离。** 独立进程读取最小必要健康信号：引擎心跳、公共输入新鲜度、私有流连续性、账户快照年龄、待决风险、UTC损失基线、保证金余量和服务端撤单租约状态。只读原始账户信息也属于私有数据，不能通过公共新闻IPC或AI服务共享。

R2的“50ms轮询、500ms超时、600ms完成取消”只是时序预算：500ms检测阈值加轮询、调度、网络和venue取消延迟，Standard账户可能远超600ms。验收应分别报告检测时间、请求提交时间、权威终态时间和最大剩余暴露；不能用发出取消的日志宣称已清空风险。

**最小权限要靠实现验证。** Lighter API key不天然等于“只能撤单”；独立key隔离nonce并不限制全部能力。riskd应通过方法白名单的signer入口只允许限定域/市场的取消与经批准的减仓动作；OS权限、socket ACL、请求长度、版本、会话generation与重放保护都要明确。不能把有广泛权限的key交给通用脚本，再称其为撤单专用权限。

**服务端scheduled cancel先做能力探针。** 官方SDK提供接口并不证明仓库固定FFI版本、具体网络、订单类型都具备相同语义。离线/本地fake venue先覆盖：设置、续租、abort、服务器时间漂移、重启、过期边界下新单、市场范围、账户范围及接口失败。是否需测试网络验证应另行授权，不能因名为testnet就自动发单。确认后可将原生租约作为riskd的补充；共享账户全取消可能干扰别的策略，必须先确定所有权与作用域。

**双进程竞争必须可恢复。** 引擎触发本地HALT后即禁止新创建；riskd持有带generation的安全状态，取消不能误伤下一轮会话。进程崩溃、网络分区、风险daemon自身失联、kill后未终态订单各有明确恢复路径。服务重启依旧经过现有账户锁与journal屏障，不能为了“自愈”直接重启交易。

**保证金与估值。** 当前 `lighter/risk.rs` 的fairmark/保证金检查已经接入策略；后续补的是多场所独立抵押品、haircut、预言机陈旧、资金费负担与压力情景。价差对冲不等于保证金对冲，USDC/USDG不可直接净额。风险估值与收益估值分开：风险用保守可执行价/折扣，绩效保留可审计现金与明确MTM。缺价格或费用不能填0。UTC日损基线与告警阈值从strategy guard持久化恢复，不能由monitor重算另一套。

故障注入的核心验收：撤单与成交竞态、重复/乱序回报、ACK丢失、nonce已消耗但响应丢失、创建尚未在open-order出现、部分成交后重启、私有环溢出、账户快照落后、funding边界、riskd与主进程断联。要求每种情况可说明“还保留多少风险、何时允许下一单”，不仅是进程没崩溃。

## 9. IPC 与性能：先证明内存正确，再证明重写有收益

R2指出seqlock数据竞争值得认真检查。当前Rust payload使用 `read_volatile`，Go在奇偶序号间写普通字段。Rust文档明确volatile不是原子同步；序号一致性检查不能自动构成跨语言内存安全证明。这是**需要专项审计的真实边界**，本轮没有做并发复现，也不宣称已证明线上发生撕裂。[Rust read_volatile](https://doc.rust-lang.org/std/ptr/fn.read_volatile.html)

建议审计交付包括：单writer所有权如何保证；序号和payload的宽度/对齐/发布顺序；字段原子读写或其他可证明同步方案；Go与Rust内存模型各自约束；x86_64/ARM64硬件差异；writer重启与共享内存重初始化；序号回绕；读者长期停顿；magic/version不匹配；时间戳与数据来自同一代际。必要时采用对齐原子整数位模式承载f64，但必须双方同步改造，不能只给Rust侧套AtomicU64便宣称修好。

迁移流程：新magic/版本/布局 → Go/Rust相同size/align/offset测试 → 合成跨进程一致性压力测试 → 平台验证 → 影子双读比对 → 明确切换/回滚。测试可用受控进程与固定数据不变量；Miri适合缩小后的Rust内存模型测试，不能单独认证外部Go进程mmap协议。深度布局以编译器offset断言为准，先修陈旧注释，避免按注释搬运出新ABI。

**观测不要拖垮热路径。** 序列跳跃、读重试、队列深度、cancel age、quote计算分位数用聚合计数与抽样；写盘和日志批量异步化。评估当前Tokio调度、锁等待、FFI、序列化、网络发送各自贡献，再决定pin core/LocalSet/专属线程。单线程也可能把一个慢签名或回报解析变成全局阻塞；2核采集机上盲目busy-spin会挤压采集与监控。

**Go→Rust与native signer的准入。** 保留现有Go采集和官方签名FFI作为基线；如剖析证明特定组件占主导，先替换一个adapter或一条路径，比较吞吐、p99、断连恢复、CPU、GC及结果等价。原生密码签名不是普通性能重构，需要固定官方协议版本、字节级测试向量、错误输入、nonce与domain隔离、密钥清理及独立审阅。没有测量证据就不把“重写完成”计为策略进步。

**地理位置按实际边际价值决定。** Lighter官方推荐AWS Tokyo `apne1-az4`，可作为实验候选，不能证明所有对手和场所都在那里。[Environments](https://docs.lighter.xyz/developers/getting-started/environments) 先在不触碰现有录制的条件下设计同源影子比较，测订单生效代理和抖动；评估跨场所最慢一腿、断连与费用。Seoul节点只在韩国公告来源的可观测领先足以抵销跨区传输和运维成本时有价值；不上来就买节点或搬主机。

**录制不能从“每次读SHM”推导完整盘口历史。** 当前latest-state-only会覆盖中间更新；要研究队列/OFI逐更新信息，应在feed校验后增加有序append tap并保留序号，而非另起轮询器声称逐帧完整。继续复用现有原始公开capture、精确时钟与湖仓，不为新闻另造一条无法对齐的时间链。

## 10. 三赛道分别如何吸收优化

### 10.1 Quant Profit：先证明防御和报价改善，再考虑事件方向交易

主线仍是已有Arcus/Lighter及有数据覆盖的市场。选少数有解释力的冻结候选，保留无Binance门控对照；在同一引擎、费表、资本、10h窗上依次比较：参考价 → 方向veto → 经济滞回 → 库存曲线 → 事件防御。不要把这些同时打开后只报告最优收益，无法知道收益来源，也无法定位退化。

核心结果：闭合周期净现金、完整MTM及估值来源、净敞口路径、最大回撤、尾部损失、每交易小时收益、资金占用、fill-conditioned markout、取消中成交占比、未完成与零成交。防御版可能更安全但交易减少，需同时展示收益损失和风险降低，不能只用胜率包装。

新闻IOC、清算捕获和链上提前布局分别建独立Quant子策略；不得混进基础MM账本掩盖方向仓位。所谓“只对冲50%”可作为方向敞口配置，但不能称中性。缺少真实新闻历史时先采集影子数据，合成新闻只验证状态机，不验证盈利。

### 10.2 Hedge Arbitrage：围绕实际可成交价差，而非报价中点

复用maker-first、basis_reversion和碎仓恢复，先把进入时的bid/ask、maker排队、部分成交、对冲触发、慢腿延迟、资金费、退出与恢复成本写全。maker成交后才有确定对冲数量；快腿成功慢腿失败不能从样本中删掉。报告R2建议3–5秒TTL只作候选，不能覆盖现有按市场/时段校准的生命周期。

每轮保留归因：入场可执行基差、maker兑现、hedge滑点、费用/返佣、funding、退出、恢复、剩余风险。盈利门槛需覆盖不确定性和极端腿失效，不把“价差大于均值几个分位数”当可执行净利。既有双所恢复和净风险限额继续生效。

RWA先验证单位和市场日历：美股常规、盘前盘后、周末、停牌、财报和公司行动分别标记；不同场所指数/预言机更新周期可造成持续基差，并非必然回归。币种相关性只能作风险模型，不能代替合约等价性。

资金费套利必须按真实interval与settlement计算。若某市场确实使用240个分钟线性权重，总权重为28920；首60分钟6.33%，末60分钟43.67%，末30分钟23.39%。这说明后段敏感，不说明提前20分钟的费率已锁定或必有套利；剩余权重、clamp、mark/index、入场费用及结算前后价差都可能改变收益。edgeX文档的4h示例只能用于数学演示，生产使用市场元数据和实际结算证据。

### 10.3 Incentive Turnover：先确认资格，再优化现金成本

四个成交额口径独立列出：目标场所成交额、双腿总成交额、已证实合格成交额、恢复/对冲等排除量；奖励分“已到账”“可计算但未到账”“资格未知”，不把估值积分提前加现金。资格未知时单位合格量成本留空，不用公开对手档位占比推算自身资格。

用户既有目标 `$100 / $50M` 换算为 **`$2 / $1M = 0.02bps`**。不能将0.2bps、2bps或按单腿/双腿切换的分母混用。负“成本”表示净现金盈利时，也要报告完整成交额、规模与完成率；小额偶然正收益不能线性外推到5000万美元。

额度、取消率、参与率、最小订单、手续费、借贷/资金费、尾仓恢复和运行成本全部计入。碎仓top-up与反向退出两笔都继续排除合格量；新增恢复机制不能制造达标量。独立账户/配置是研究隔离，不是允许共同控制账户互成交；沿用fleet隔离并补owner级防护。

**本轮对既有w01/w02结果的态度。** handoff历史日志记录了570个试验及一些正结果，本轮没有重新读取原始Gold或复跑，因此只保留为既有selection证据。多次调参同一窗口会增加选择偏差；不能把“570组零引擎报错”理解为570份独立盈利证明。三赛道HOLD不因本方案写完而变化。

## 11. 事件进攻与链上先行信号：保留研究价值，降低证据等级

R1的“链上先知”和R2的提前布局，本质是在公开信息传播前后预测资产事件。可研究的输入包括公开合约部署/权限变更、已验证的上币公告、做市或托管地址行为、公开代码变更。不能把一个地址标签、GitHub PR或白名单更新直接当确定上币，也不能用后来知道的标签反向解释历史交易。

**第一阶段只建事件数据集。** 每个候选保留首次发现时间、当时可见字段、资产身份、来源关系、最终结果、结果首次可确认时间，以及未发生事件和误报。区分已确认区块、未最终确认区块、mempool可见性与重组；公开mempool并不覆盖私有交易。地址归属带来源和有效区间，禁止从单次转账推导永久“知情人”身份。

**Bayesian更新需要可校准模型。** R1的 `L←L−ηΔt+Σlog(LR)` 会在无新事件时趋向负无穷，而不是回到先验。可研究的遗忘形式是 `L←L0+exp(−ηΔt)·(L−L0)` 后再加入经独立性处理的证据项；这只是候选模型，LR与基准发生率必须在训练集估计。把同一公告的转发、同一资金链的多跳和AI重复摘要当独立证据会让概率虚高。按事件而非消息随机拆训练/验证，使用可靠性图、Brier/log loss、稀有事件召回和误报成本评估。

0.35 Kelly不能修复错误概率或厚尾损失。初期即使出现校准信号，也先用固定小风险上限的纸面仓位评估，在流动性枯竭、跳空、归零、交易暂停和高相关事件下算组合损失。模型概率不是交易仓位百分比。

**新闻IOC的可执行优势门槛：** 到达我们系统后仍存在、动作生效时仍存在、扣taker费/滑点/资金费后仍为正，且盘口能支持目标规模。不能以“Binance随后涨了”标成我们可获利。需要与“只防御、不进攻”的策略对照，加入未成交、部分成交、价差反转、消息撤回和市场已提前反应样本。

TWAP/分片仅作为降低冲击的执行候选，不以隐藏身份或规避平台控制为目标。对手活动只能基于可合法访问的公开成交统计，不能将推测的地址身份写成已证事实。时间止损不会消除平台冻结/无法成交风险；reduce-only同样可能失败，必须保留待决状态和终端损失预算。

反欺骗测试包括：同名币、错误链、旧新闻重发、伪造公告文本、新闻正文提示注入、源站时间倒退、修订撤回、相关来源“多数票”、成交量造假式异常与上币后流动性坍塌。未经证据门控的“置信度高”不得触发实盘。

## 12. 数据、回放与统计验证：让优化结论能被推翻

**A. 一个试验身份对应一套不可变输入。** 延续 [数据源登记](RESEARCH_DATA_SOURCES.md) 与Git外append-only campaign inventory。新增新闻/链上/费用规则都记录source、domain、市场、时间范围、hash、可用时间规则、缺口、转换、版本及失败；官方网页可记录公开内容版本/摘要hash，绝不把带鉴权响应混入公共证据。先查inventory再说“没有数据”。保留旧结果，修复后以新engine/config/fee/input hash生成新身份。

**B. 区分三种窗口，不能补写历史。**

**D. 在同一因果引擎中模拟真正可执行动作。** 新闻按revision availability加入；每个动作分别累加客户端处理、网络与venue延迟。Maker激活前不能成交；cancel pending期间可成交；IOC按生效时可见深度、价格保护与已消耗流动性匹配，禁止读取未来深度或无限重复使用同一档。保留queue ahead/部分成交/迟到回报，不把bid/ask触碰当必然成交。无法由L2识别的撤单位置用保守/中性/乐观边界并列，不隐藏结构不确定性。

**E. 小矩阵回答明确问题，再冻结少数候选。** 基础执行纠错对所有arm一致生效，不能当alpha收益。建议第一轮每个选定市场控制在约10–12个可解释arm，具体数量在预注册时定：

| --- | --- | --- |

**F. 衡量防御与进攻使用不同终点。** 防御优先看cancel-pending adverse fill、事件窗尾损、最大暴露时间和误停成本；进攻优先看机会级净现金与失败尾部。共同指标包括完整成交额、参与率、资金占用、净现金/交易小时、最大回撤、费用/资金费分解、覆盖缺口和未完成状态。50/250ms markout只有在数据分辨率和标签容差满足时发布；沿用现有100/500ms、1/5/30s等可支持指标，不回填未来价格。

**G. 统计单位是有依赖结构的窗口/事件，不是数亿行情行。** 对同输入策略做配对比较，按连续时间块、交易日或完整事件聚类估计区间；明确窗口间相关性和稀有事件数量。按正常/新闻、周末/美股时段、上涨/下跌、波动/深度分层，层级事先声明。`K>=10`10h窗只是采集/运营目标，不保证统计充分；没有足够独立事件就报告无法判断。

晋级前预先确定：主要终点、最小经济改善、置信区间方法、最大允许尾损、覆盖门槛、失效阈值和停止规则。不得看完结果再移动门槛。Quant至少需要扣完整成本的正证据；Arb需要双腿闭合及失败成本可承受；Turnover需要已验证资格下的成本目标和可扩展成交量。任一必要条件未知，维持HOLD。

## 16. 结合现实与代码的 RWA 专项适配

### 16.1 先区分产品，再迁移做市原理

传统研究并非没有股票；它缺少的主要是今天各RWA永续的具体包装：不同部署者的预言机、合成收益、交易时段、抵押品、价格限制和结算规则。因此既不能原封不动照搬，也不必重做库存、队列和逆向选择的基本理论。

这里的“RWA”是研究分组，**不是一个可交易的统一资产类型**。当前 `AssetClass` 只有 `Crypto/Equity`，字符串 `underlying_id/payoff_id` 已提供身份约束，但不能据此宣称任意RWA产品已获模型支持。扩展优先在现有能力/合约元数据边界落实，只有语义需要时才增加类型。

| 产品 | 必须核对的真实收益口径 | 在本项目的处理 |
| --- | --- | --- |
| 已上市个股永续 | 公司、上市地、普通股/不同股类/ADR、每合约股数、除权除息处理、外部价格和结算币 | 同ticker不足以配对；同公司ADR与本地股票还需存托比例、FX和时段转换 |
| ETF或指数永续 | ETF份额、价格指数/全收益指数、期货或现货参考、分红和跟踪偏差 | SPY与SP500不是同一可交割资产；需要专门的残差风险模型，不能直接通过同收益配对 |
| 商品、FX、利率相关产品 | 现货/期货合约月份、滚动方式、报价单位、币对方向、参考市场时段 | 不能为了复用runner把类型改成Crypto；月换仓、节假日和单位变动另建规则 |
| Pre-IPO / Prelaunch | 参考的是预期上市或其他事件；未来转换/结算方法、取消/延期及参考缺失 | 单独准入，不能假装已有可连续交易的股票对冲腿 |
| 股权代币或有赎回权产品 | 持有人法律/经济权利、赎回条件、托管与转让约束 | 本次永续采集不自动覆盖这种产品；需要新的产品证据 |

TradeXYZ当前官方说明其永续是USDC保证金与结算的线性合约，USD oracle不做USDC/USD换算；这是需要记录的quanto式经济敞口。其Pre-IPO说明也明确合成头寸不代表股份或IPO配售权，上市前可能没有可靠连续公共价格。不能把这两种产品理解成买到并可交割的现货股票。[永续定义](https://docs.trade.xyz/perpetuals/)、[Pre-IPO产品说明](https://docs.trade.xyz/legal-and-disclaimers/perpetuals-risks-and-disclaimers/pre-ipo-perpetual-markets-risks-and-disclaimers/)

### 16.4 时段、参考和公司行动的因果数据合同

为现有Frame或独立状态事件补合同，先定语义再选最小实现。至少包含：`instrument_terms_version`、参考源/市场、`source_time`、`first_available_at`、本地receipt、`mode`、有效区间、calendar版本、halt/resume状态与首次可见时间、公司行动覆盖截止及payoff版本。这些是**建议字段**，不是现有schema声明。公共状态不写入私有V2环。

需要区分五类时段：底层核心连续盘、允许的盘前/盘后/24×5外部市场、纯内部定价休市、停牌/异常参考缺失、公司行动/转换边界。状态按venue和instrument记录；不是所有美股都在同一瞬间有同等可执行参考，更不是所有RWA都使用纽约时间。

1. **已知日历与突发事件分开。** 节假日/计划提前收市可以在发布后提前使用；临时停牌要用首次可得通知，不能把事后确认的整个停牌区间提前喂入策略。`prepare_equity_replay.py`现有停牌输入可做历史情景；若拿它证明在线撤单收益，需补观测延迟或做明确的延迟敏感性。
2. **新消息与新信息分开。** 10:00收到内容仍为昨收的更新，receipt新鲜、底层价格仍旧；内部oracle每秒变化也不变成独立股票现货。三种时间分别保留，无法证实时标unknown。
3. **参考是有条件的。** regular-session minute close适合较慢的basis/覆盖诊断；不作100ms微价、queue或news alpha真值。跨过休市的1s/10s标签若无合格参考，标缺失/跨制度，不能重复昨收给出零markout。
4. **公司行动是收益口径变化。** 拆股/合股、现金或股票分红、ADR比例、并购换股、ticker迁移和Pre-IPO转换分别核对各腿规则。未知窗口拒绝新风险；不能把事后复权数据回填为当时可交易价格。没有行动证据不等于没有行动。
5. **保留当前持仓处置能力。** 禁新风险、取消请求、确认终态和仓位归零是不同状态；交易暂停或参考失效不证明订单已经撤掉，也不凭空产生可成交的退出价。到达截止前未平/未决必须作为未完成及敞口保留。

拟议传播路径：公共事实及条款 → 因果Frame/状态事件 → 路径专属准入 → 报价与在途订单检查 → 带制度标签的账本/markout。maker-first可扩展状态事件，或消费带版本/范围/时效和拒绝原因的上游准入证明；单一 `tradable=true` 无法表达此合同。是否支持纯内部休市模式应是显式策略选择，不能靠漏传字段意外开启。

### 16.5 把 Vertox 模块改成适合 RWA 的条件模型

**Fair price与basis。** 保留weighted-mid/现有allowlist作为基线，但只汇聚身份、参考模式和时效相容的输入。参考切换、开盘和公司行动后，重置/隔离相应basis、波动和fill统计，等待预热；不能用EWMA把单位错误或产品错配吸收成“正常价差”。现货、ETF、指数、期货和不同部署者的内部oracle各自保留来源。Binance BTC可作为待验证的全市场风险因子，不能直接当NVDA的公允价。

**同一个量价信号在不同时段有不同含义。** 核心盘以独立参考及本所可执行价共同评价；有可靠盘后参考时单列流动性和lead-lag；内部休市时先验证是否有足够的跨永续价格发现及风险容量，不能强制回归最后现货价格。价格到达边界后的队列拥挤、流动性撤离和重开跳跃要进入压力情景。模型的预测基准、收益结算基准和可执行对冲价不能混成一个fair。

**Fill与队列。** 用时段、参考模式、事件、队列区间、spread/tick、订单年龄和动作生效延迟条件化fill hazard与markout。先解释开收盘季节性再拟合Hawkes，否则确定性的流量高峰可能被拟合成“自激”。停牌/断流属于风险状态或删失，不能当作长串正常零成交。主市场集合竞价可以作为外部价格事件；本所CLOB排队规则另算，不能互相复制。

**库存与期限。** A–S中的剩余持有风险不能因为永续24×7挂牌就设一个永不变化的常数。研究用的风险期限至少受下一次已知参考切换、关市、funding、事件、可靠对冲能力和终端drain约束；不同机制可以有不同窗口，不必硬塞成同一个T。对已有库存，跳空损失与可清算容量使用独立压力预算；先缩量/禁增仓/受保护退出，再研究更复杂skew。不是简单把全天σ调大就足够。

**Markout与学习。** 每笔保留本所可成交基准、独立参考基准、来源模式和覆盖率；不能以自己预测的fair给自身策略打分。跨公司行动先统一合约数量与价格口径；跨休市标签独立统计。fill-conditioned改善也需检查选择效应：少成交可能剔除了坏单，也可能只剩偶然好单；必须同时看未成交暴露、撤单在途损失、现金和容量。

最小候选顺序：条件化现有基线 → 按时段的简单alpha/库存保护 → 队列与撤改单经济性 → 有增量证据再GLFT/Hawkes。RWA不是为所有候选统一增加一个“资产类型系数”。

### 16.6 R1 新闻体系在 RWA 上如何具体使用

把 `tradfi/tfmoves` 等资讯频道作为候选发现入口；该频道存在不证明其财报、宏观或停牌覆盖完整，也不证明延迟适合抢单。新增事实类型分别处理：

| 类型 | 因果字段与交叉核对 | 首轮允许的用途 |
| --- | --- | --- |
| 财报、指引、回购或融资 | 发行人/证券身份、财政季度、币种、EPS口径、修订、首次发布时间；惊喜值还需当时可见的同口径一致预期 | 事件窗口缩量/防御；有方向标签后再独立Quant影子 |
| 宏观、利率决议、通胀/就业 | 发布时间与可用时间、初值/修订值、指标单位；各个股/行业/指数的历史敏感度 | 组合风险预算和事件窗口，不用“利好/利空”二值文本直接决定每个股方向 |
| 停牌、恢复、公司行动 | 主上市地/交易所和各永续部署者规则的身份、有效时刻、首次可得时刻及冲突 | 硬准入与恢复状态，不当普通情绪alpha |
| 产品规则、oracle/保证金/合约转换变更 | 对应venue/domain/market与新旧版本、已知生效窗口 | 阻止旧规则继续接新风险，触发重新验证 |

一手来源候选是发行人IR、监管披露、主上市交易所通知及场所产品公告；先检查注册表与已有归档，再补实际缺口。不是新增所有候选源即算数据覆盖完成。更正/撤回、重复转载、同公司不同股类、预期与实际混写，都要做fixture；没有可回放的真实首次可用时间时，只能验证防御逻辑，不宣称“比市场提前获知”。

R1的μ、置信度与mode应由已验证事实驱动；RWA首轮仍按OPT-07的确定性降风险合同接入。新闻方向进攻、清算捕获、Pre-IPO投机与链上布局各自维护Quant子账本，不进入市场中性套利或激励收益。

### 16.7 R2 执行与资金模型在 RWA 上如何具体使用

两腿持仓delta接近抵消，只减少特定参考价格风险；不能消除basis、USD/稳定币、保证金、平台/部署者、清算和转换风险。不同HIP-3部署者可以是不同流动性域，但仍共享部分清算/基础设施风险；现有 `allow_shared_risk_domain` 是显式接受条件，不是独立风险的证明。

建议把每轮经济量拆成：成交/对冲/退出现金，交易费，**已结算**funding，借贷/抵押资金成本，已确认公司行动调整及未平风险。预测funding单列；不把预测值填入实际现金。低funding乘数可能让某种basis更难由持有成本压回，是否发生必须测量，不能认定“低资金费就是便宜对冲”。真实结算时刻、适用头寸、支付资产和当时规则都要与精确成交覆盖匹配。

Backpack的AutoLend/借贷或其他场所的跨抵押功能若纳入候选，需要独立估计借入利率、抵押折扣、追加保证金、提取/转移延迟和失败，不能让同一笔资本同时为两个独立赛道提供全额保证。基础期望收益之外，分别计算每腿可退出容量、关市期间资产价格压力、稳定币折价和资金被占用时的损失预算。账户实际能力未知就不能假设转账立即完成。

既有 `flat_at_funding` 解决的是特定结算前后头寸合同。新的RWA模式还需要审计 `min(end, eligible_session_end, action_clear_until, funding_deadline)` 等各自适用的动作截止，并预留创建、成交通知、对冲到达与取消终态时间。不能直接用这个表达式覆盖全部策略：允许持有funding或内部休市的策略必须另有显式合同；已持仓失败退出仍要留真实未完成状态。

成本与激励继续分账。分母保留目标场所量、双腿量、合格量及恢复量；奖励未知不填入净现金。不能拿RWA周末较低费率或样本中净零库存直接外推到更大规模。

研究合同中的10h是**连续验证单元**，不是强迫策略交易10h。若只获准交易美股核心时段，一个10h单元可以含6.5h核心盘及其余禁新风险/观察时间：必须保持同一现金、库存和预算状态，完整报告剩余3.5h的用途，不能称10h有效市场暴露。更短核心盘、延长时段、周末内部定价、财报和异常状态分别标记实际覆盖；没有覆盖就明确缺少，不在中间停钟或跨日拼接。
