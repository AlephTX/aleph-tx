## 1. 基差分布与筛选结果

[完整机制及 48 臂结果](BASIS_RISK_SELECTION_2026_11_14.md)。用户转来复核时该矩阵已经
冻结开跑，没有根据中途结果修改参数。随后新增 `audit_basis_range.py`，只读同一公开
磁带，不启动订单引擎，独立保存统计身份。它不是新的 holdout，也不授权继续对旧窗调参。

只读诊断采用本地顶层盘口的 tradable、单调时间、新鲜度和双腿时差约束；不模拟
全深度 tick 校验、仓位、资金费暂停及订单可成交性。时间权重在下一事件、数据过期或
观察间断上限处截止；不是按消息数量统计“时间占比”。样本分位数另标为样本口径。

| 指标 | BTC | ETH |
| --- | ---: | ---: |
| 十小时内可计算极差的时间比例 | 88.70% | 91.17% |
| 可计算时间中极差处于 `(0, 3)` bps | 92.36% | 84.32% |
| 极差达到 3 bps 的时间比例（可计算时间为分母） | 7.64% | 15.68% |
| 样本极差中位数 / p90，bps | 1.453 / 2.803 | 1.817 / 3.471 |

因此，“大部分时间在上下限、难以区分三组”的前提未获本窗支持。更直接的观察是：
在每目标成交额 2 bps 的预算下，把额外风险准备金作用于预计**双腿总成交额**，
会消耗本已很薄的空间。动态臂虽仍产生少量挂单，但没有成交。
零现金损失、零成交不能算更好的激励效率；不按这个结果上调风险或损失预算。

方向统一为“目标场所相对参考场所较贵为正”。本轮使用
`r_bps = 10000 × (target_mid/reference_mid - 1)`；未来 C 组若使用
`log_basis = ln(target_mid/reference_mid)`，转换为 `r_bps = 10000 × expm1(log_basis)`。
两者符号相同，单位不同，禁止把 log 值直接当作 bps。此次不改变已冻结计算公式。

旧 `resets` 保留为“实际清空非空历史的次数”。新增 `reset_events` 统计所有失效调用，
`trade_feed_offline_events` 单列断流通知，即使还未预热也计数。失效调用不等于独立故障段；
重复无效盘口可能多次计数。只读审计也同时报告两种口径。

## 2. Binance 归因：保持原量化实验不变

新增按 bid/ask 分开的 shock 与 unavailable 目标撤回数；unavailable 包括陈旧、缺失、
预热不足和失效历史。两类之和必须等于原目标撤回数。新增决策口径的新鲜参考占比，
无决策时为未知。记录模式 A 同样报告参考状态，但不撤回目标。

这些是**报价目标次数**，不是已成功撤单次数，更不是两种原因分别造成的现金收益。
现有 A/B 本身不能独立识别“缺失过滤”的 PnL 效应；后续量化实验应加 stale-only 对照。
原八臂冻结源码、配置、引擎、输入和结果不变。新诊断用
`audit_binance_attribution.py` 对同一输入复跑，逐项比对完整原报告，
只容许新增诊断字段不同；任何决策/成交/现金差异都使该臂归因无效。

```sh
python3 scripts/audit_binance_attribution.py \
  /absolute/diagnostic/maker_replay /absolute/original/frozen \
  /absolute/original/results /absolute/new/audit-output
```

一阶信号仍是价格变化。`bookTicker` 的数量是挂单数量，**不是同步成交额**；
不能以它代替成交量冲击。未来若研究价格乘成交流，必须先增加带同机可用时间的
`aggTrade` 输入，独立冻结新机制并计入漏成交、撤单等待损失和手续费。

## 3. HL / HIP-3 撤单：独立量化实验协议

官方 [HyperCore order book](https://hyperliquid.gitbook.io/hyperliquid-docs/hypercore/order-book)
确认每个共识批次按动作类别排序，取消在发送 GTC/IOC 的动作之前；这不是跨所有批次
的“撤单必胜”。[延迟说明](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/optimizing-latency)
还将 mempool 优先级与 Standard abstraction、动作类别等条件关联，并区分普通取消与
不能用于 trigger orders 的 fast 取消。这里的 Standard abstraction 不是 Lighter 账户层级。

[Arrakis 研究](https://arrakis.finance/blog/crypto-price-discovery)使用截至 2026-02-26 的
16 天、29 个加密标的和 100 ms 搜索步长。约 700 ms 是历史成交序列的相关性滞后；
不是当前 Oasis 发单预算，更不是 NVDA/SNDK 上已测得的优势。

该实验不等待 Lighter 盈亏结论才立项，但须先完成以下独立准入：

1. 每个目标域、标的保留同机 Binance/目标盘口及逐笔成交的源时间、接收时间、可用时间。
   加密参考只用于同标的；股票参考先过下节的合约核查。
2. 独立四臂：原本地做市、仅参考失效过滤、仅新开仓方向过滤、方向过滤加存量风险订单撤回。
   后三臂共享同一参考失效规则；同一配置之外不混合资本和现金。
3. 保留待撤敞口、迟到成交、对冲及库存退出。不得把“发出取消”当作订单已不存在。
4. 没有批次/排序证据时，保守模型仍允许取消等待期间被打；100/250/500/1000 ms 只能标为
   延迟敏感性，不宣称实测延迟。批次优先的反事实结果单列，不计入已认证收益。
5. 单列撤回前后 fill markout、丢失的有利成交、挂单时长、队列损失、完整净现金及库存。
   冻结新的连续十小时，分别报告每个 Entropy/XYZ 市场。不得借用激励预算为量化结果兜底。

## 4. Arcus、BULK 激励资格与 RWA 套利

本轮尝试打开 Arcus Points、Protocol Terms、RWA/funding 官方页面；浏览及直接公开
抓取均失败。没有新的证据证明“持续双边报价”或“盘后持仓”明确获得积分；此前设计
引用的做市/存款类别不等于这两个行为得到保证。保持待核实，不能据此自动化入金。
“盘后波动低、资金费静态 SOFR、逆向选择小”也未在本轮证实；停市新闻跳空和退出流动性
仍应独立测量，零 maker 费不等于低完整周期成本。

依据此前保存的 Annex C 风险，Arcus 激励主线移向规则核查、报价质量和抵押品占用；
不预认证主要以积分为目标的对冲循环。正常套利仍可单独研究，但不拿它的交易量给
激励账本计奖励。资格未知时，**每百万合格量成本未定义**，不是偏保守估算；报告新增
`confirmed_cost_bps_per_eligible_turnover: null`，情景分母与已确认产出分开。

本轮重新读取的 [BULK Challenger 官方规则](https://docs.bulk.trade/bulk-exchange/aura)
明确排除 market makers，且保留平台资格判断。做市返费实验与参赛产出必须分开；
即使另设研究账本，也不能推断同一参与者因此变得有资格。

io/xyz 的 NVDA、SNDK 套利分别使用下面核查表，全部通过后才生成交易配置：

| 检查项 | 必需证据 |
| --- | --- |
| 单位 / payoff | 交易单位、股票/ADS/拆股调整、标的 ID、报价币、结算币、合约乘数 |
| 市场状态 | 开闭市、盘前后、周末、停牌、价格上下界、oracle 更新及回退规则 |
| 资金费 | 公式、倍率、结算频率、实际已结算费率和持仓时间水位；不年化替代现金 |
| 完整退出 | 双腿深度、最小量、费率/Growth Mode、共同退出时段、部分成交和 FX 成本 |
| 实验隔离 | 专属资本、亏损预算、订单状态、资金费/返费现金账本；积分价值为零 |

价格接近只用于候选筛选；不会以相同股票名称跳过这些检查。
